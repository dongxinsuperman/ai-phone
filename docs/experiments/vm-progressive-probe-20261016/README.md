# 三端下发探查逐台展示

日期：2026-10-16。基线为个人仓库 `32966de`，本次只调整 Android、iOS Simulator、Harmony 的候选探查及展示。

## 用户看到的变化

以前页面等全部 Agent 返回或整批超时，再展示候选。现在先列出当前在线 Agent；每台独立显示探查中、可下发、不可用、通道异常、超时或离线。已确认可用的行立即允许下发，不受其他行等待影响，列表位置不随着结果跳动。

关闭列表、切换当前探查配置或离开页面时取消本轮接收；选定一台下发后结束本轮展示。迟到的旧结果不能覆盖新列表，不自动重试探查或下发。Android 原有“只有一个可用候选时自动下发”仍在整批完成后判断，绝不把最先返回当成唯一候选；用户手动选择优先。

取消会释放 Server 本轮等待与未完成发送；已经送到 Agent 的一次只读扫描可能继续完成，其迟到结果不再进入这轮列表，也不会触发绑定或启动。本次没有增加远端扫描取消协议。

当前系统只有在线 Agent 快照，没有离线 Agent 的持久名册。因此“全部”指本轮开始时系统已连接的全部 Agent；探查途中掉线会单独显示离线，不增加历史 Agent 管理功能。

## 实现与兼容边界

- 沿用原三端 `POST .../instances/{id}/dispatch-candidates`，新增可选查询参数 `stream=true`；默认仍返回原 `request_id/agents` JSON，旧 CLI 不需要为本次展示增量升级。
- 流模式使用同一次已鉴权 HTTP 请求，逐行 JSON 依次发送 `snapshot`、各 Agent 的 `agent` 结果和 `done`；没有增加路由、数据库表、列、后台补单或 Agent 消息类型。
- 发送并行进行；整批仍有一次 60 秒截止，每次发送也有原有的有界等待，一台发送卡住不能排在所有机器前面。
- 读取配置并准备消息后归还数据库连接，避免探查等待占满连接池、拖住随后下发。
- 每份结果核对请求和 Agent；断线、超时、取消后不能由迟到能力回包恢复可用。鸿蒙端口缓存只接受有效回包，较旧探查不能覆盖较新的结果。
- 真正下发继续走原生命周期与实时校验；iOS/鸿蒙只复核选中的 Agent，其他机器不再成为页面选择的前置条件。端口池、绑定、停机、删除和数据保留规则不变。
- 页面与 Server 应配套更新。流设置 `Cache-Control: no-cache` 和 `X-Accel-Buffering: no`；部署中间代理也必须允许逐块转发，不能把完整响应缓存完再交给浏览器。本次现场验证限定本地 HTTP，没有冒充公司代理验证。

此次增量不要求更新 Agent 原生工具，也不要求重建已有虚拟机。若尚未部署前一轮生命周期修复，仍按原升级交接配套更新，不能把这里的展示兼容说明推广成任意新旧版本可以混跑。

本次改善“已有可用机器还得等最慢机器”的时间，不宣称让某台电脑的 SDK/镜像枚举本身加速，也不保证探查成功后环境永远不变。

## 与快速下发直接相关的并发保护

独立复核发现并修正了两处边界：旧断线处理在数据库等待期间遇到同 ID 重连，不能再把新会话的启动操作判失败；鸿蒙本次成功探查得到的占用端口，不能因另一份更晚但缺少端口资料的探查覆盖缓存而丢失。前者复用已有 VM 事务锁并在锁内重新确认连接与归属，后者把本次实际结果直接合入端口排除集合；没有新增重试或会话编排系统。

## 验证

最终统一回归 **1622 passed / 2 skipped / 73 warnings**，78 个测试文件；2 个跳过仍是原有 Android 不适用分支。前端 **77 项通过**、构建通过；真实浏览器 **54 项通过**、6 张截图，三端均验证慢发送/慢回包仍在途时能点击快行，并经真实下发路由只发送一次。不同层次的计数不相加。37 个产品文件及测试/构建摘要已核对；临时服务、数据库、浏览器和探查等待均已清理。[最终验收摘要](acceptance-summary.json)、[统一回归](regression-evidence.json)、[浏览器结果](browser-report.json)。

测试使用个人隔离数据库、可控 Agent 桩和本地浏览器，没有访问公司服务、默认 CLI profile 或真实设备；Fake Agent 仅确认传输接收，不伪造原生启动验收。独立代码复核无剩余阻断。Android 最后仅修正长名称挤压按钮的样式，并重做统一回归、构建及浏览器验收；此前通过记录保留在 `before-button-nowrap/`，不覆盖或重复计数。

后端定向阶段的 [218 passed / 2 skipped 记录](../vm-probe-stream-20261016/backend/final-evidence.json)保留原样；该阶段护栏拦截过一次 urllib3 导入时的 IPv6 临时绑定检测，具体栈见[校准记录](../vm-probe-stream-20261016/backend/guard-import-calibration.json)。实际绑定未发生，不能把原始 `blocked_calls` 写成空数组；最终统一回归和本地浏览器夹具的护栏记录均为空。浏览器第一次准备因测试数据漏填 Android 必填字段退出，未启动监听或创建原生 VM，修正夹具后再验收；原日志为 `browser-fixture-preflight.log`。
