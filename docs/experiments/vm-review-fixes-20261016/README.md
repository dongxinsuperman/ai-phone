# 两项审查问题的修复与复验

基线：`578fb71`。仅在个人项目工作树修改，测试使用临时 SQLite、受控 Agent 回包、假时钟及原生命令替身，不操作公司环境或真实虚拟机。

## 修复范围

1. 换 Agent 退旧建新后，如果目标掉线且新配置尚未发出任何启动操作，保留失败原因，并允许用户再次使用原有下发入口；不自动续单，不恢复旧账，不重新分配另一个新 ID。
2. iOS、Harmony 的普通停止贯穿同一份剩余预算：Server 携带本次预算，Agent 从收件开始扣除队列时间，handler 在发送进度前建立本地截止时间，后续线程排队、等锁和原生命令继续使用该截止时间。

第一项仅适用于锁内确认仍是未使用的新配置；已创建、创建来源不明、或被另一个操作接管的实例不因此放行。失败结束与下一次用户主动下发仍是两次独立操作。

第二项在剩余时间耗尽后不开始后续关机、强制信号或资源释放，不把仍未确认的实例从本地登记中提前摘掉。已经发出的底层命令可能仍需结束，不能用取消 Python 等待冒充命令已经退出。原有 Android 停止/删除预算保留；本轮不扩展 iOS/Harmony 删除命令的预算设计。

资源容量预估继续只作提示：不增加磁盘、内存或参考实例数量的下发硬限制，不增加二次确认。原实例数据、身份和实际端口冲突的保护保留。没有新状态、新业务重试、新表或数据库迁移。

## 原始反例

`before-review/` 保存基线独立复现原件：三端各一个换机失败后无法再次下发的反例，加上两端停止在进度发送、线程排队、实例锁三个阶段耗尽预算的六个反例，共 **9 个违规反例、5 个正常对照**。这批记录是修复前的失败证明，不改写成通过记录，也不覆盖前轮测试。

`backend/tests/test_vm_review_regressions.py` 保留同一 HTTP/WS 到原生停止入口的场景，并加强超时终态和身份保留断言，避免桩接口错误产生“没有执行命令”的假通过。各平台专属测试覆盖剩余 timeout 传递、信号升级、严格身份查询、普通停止和既有删除兼容。

按用户最新要求，本轮验收仅限这两项缺陷及其直接调用路径，不执行全局回归。已完成的结果直接复用；最终核对原 9 个反例和 5 个正常对照、Stop 预算专项及因本次签名变化而确实受影响的单个测试节点。各分项计数不重复相加。

## 最终结果

- 原 9 个反例与 5 个正常对照均通过；直接复用 `harmony/regression-r1.xml` 中对应的 14 项，已核对记录的产品源码指纹与最终源码一致。
- 复用 Server、iOS、Harmony、WS 已完成的专项结果，不重新运行或把重叠计数相加；最终仅对签名确实受影响的 3 个旧 mock 测试节点补验，全部通过。
- 已启动过的旧组曾有 3 个 mock 签名不兼容失败；原失败记录保留，修正后 3 个精确节点的通过记录另存。一次 helper 选择器透传失误额外跑了 14 项，通过但不冒充那 3 项的验收，详见 Harmony 分项记录。
- 窄范围独立复核无剩余 P1/P2 阻断。三端容量探查文件与基线字节一致，资源估算仍作提示。本轮没有前端改动、数据库结构变动或 CLI 协议破坏性变更。
- 本轮测试没有启动真实虚拟机，不宣称重新完成原生三端验收，也未访问公司服务。产品源码、针对性结果及限制统一记录在 `final-verification.json`。

变更只修正换机失败后的再次手动下发，以及普通停止的时间预算；继续使用现有下发、启动、停止按钮。Server 与 Agent 应一起更新，本地更新记录单独保存，不把服务健康检查算作上述缺陷测试。
