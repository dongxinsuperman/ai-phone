# 原 23 项审计逐项归档

本表记录首轮 `74f209d` 对原 23 项的处理；交接补查新增的升级误删、发送失败/CLI 兼容、包操作占用和 Android 缓存问题已另行修复，完整现状以 [升级交接说明](../../../vm-lifecycle-upgrade-guide.md) 为准。

编号对应基线 `452e7d7` 的原始证据，不把仍然存在的技术限制标为已消失；最终业务约定优先于早期审计提出的方案。

| 编号 | 最终处理和边界 |
| --- | --- |
| E01 候选等待最慢 Agent | 保留一次请求返回整批候选的接口，因此无响应 Agent 仍可能让查询等到 60 秒上限；本轮没有增加流式候选协议。 |
| E02 发送失败仍空等 | 已修复：发送失败计入完成条件，全部发送失败立即结束，不继续空等。 |
| E03 鸿蒙探查重复且重 | 已修复重复静态检查：按工具、镜像、配置指纹短时缓存，端口和内存仍实时检查。 |
| E04 超时预算不一致 | 下发预算贯穿接收、排队、实例锁及原生命令，截止后结果不能重新绑定；原生子调用无法强制打断时只允许完成自身有限收尾。 |
| E05 跨平台串行扫描 | 已修复：四类发现工作独立、每类单个在途任务，慢平台不再串行拖住其他平台。 |
| E06 扫描重元数据/驱动 | 已限制影响，但没有重写各平台原有驱动发现流程，首次取元数据仍可能耗时。 |
| E07 扫描并非固定五秒 | 按实际收到结果的时间与可信度判定，超时快照不当作可靠就绪；不宣称任意设备都能五秒发现。 |
| E08 慢生命周期阻塞指令 | 已修复：VM 操作有界并发、同实例顺序执行，接收循环继续处理原有任务和控制消息。 |
| E09 首次 hello 同步扫描 | 已修复：发现工作离开事件循环，并使用统一的扫描与发布顺序。 |
| E10 重连恢复等待 | 已缓解：三端前置恢复并行、静态预热旁路；连接恢复钩子仍保留顺序，完整收发会话不能承诺瞬时恢复。 |
| E11 WDA 自愈阻塞 | 已修复：维护工作离开事件循环，先取得设备维护占用再核对任务和观看状态。 |
| E12 超时线程继续存活 | 已限制影响：独立有限线程、有限排队和底层时限；Python 无法安全强杀任意第三方同步线程，不把外层 timeout 当作线程已经退出。 |
| E13 健康结果等整批 | 已修复：单设备完成即处理，上报带实例身份与代次，过期结果不恢复可调度状态。 |
| E14 旧扫描覆盖新扫描 | 已修复：统一单轮扫描与发布，合并重叠刷新，未完整查询不作为删除证据。 |
| E15 Android 失联遗忘进程 | 已修复：保留原生身份，按实例和进程核查，ADB 缺席不等于虚拟机已停止。 |
| E16 iOS 缺席永久失管 | 已修复：受管身份与临时设备可用性分开，扫描失败不撤销原实例纳管。 |
| E17 iOS 停机假成功/失败遗忘 | 已修复：核对真实 shutdown/absence，失败保留证据，停止保留原数据和端口归属。 |
| E18 鸿蒙失联直接关机 | 已修复：通道异常降级报告，保留实例及租约，不因一次设备列表缺席主动关机。 |
| E19 Android 端口分配与改选 | 已修复：Server 事务内分配，Agent 不偷偷改端口，避开仍被任务锁持有的旧 serial。 |
| E20 鸿蒙注册表并发写 | 已修复：一致快照、串行保存与唯一临时文件，避免不同 VM 互相覆盖临时文件。 |
| E21 iOS 查询失败后替代创建 | 已修复：查询不确定就失败，重启不隐藏重建，复用实例的数据不被首次绑定回滚误删。 |
| E22 容量与设备占用 | 已修复任务、安装、观看和维护之间的占用冲突；保留原有内存/数量软提示，未新增跨三端内存配额或自动扩缩容调度器。 |
| E23 删除与回报收尾 | 按用户最终要求改为立即删账和重连清残留；一次操作的有界结果补送、操作 ID 与截止时间阻止旧状态覆盖新账，不引入清理墓碑和后台续单。 |

## 本轮新增发现

- Android 真机模拟器进程退出后的 TIME_WAIT 与真实监听占用需要区别，已修正并通过原生复验。
- 鸿蒙清理失败需要同步记录进程、目标、端口及采样耗时，已补有界证据；未根据事后空闲放宽删除规则。
- 同名 Agent 会话、同宿主新会话、迟到回报、换机并发异常和可选 VM 表缺失均新增了独立回归。

## 不能从本轮结果推出的结论

本轮交付基础生命周期的事务、身份、对账与占用保护；不是跨宿主容量调度系统。高频并发扩缩容仍需明确每台宿主的容量策略并做负载验收；Windows 宿主、iPad、真实手机和生产 VLM 业务没有本轮现场通过证据。冷扫描、整批候选等待和原生启动成本仍需分别看待，不能把普通操作通过写成所有性能问题均已消除。
