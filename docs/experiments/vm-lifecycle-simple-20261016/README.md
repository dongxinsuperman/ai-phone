# 普通启停与统一状态：2026-10-16 增量

本轮接在 `82e48bc` 后，处理页面“已停止却要求重试停止”“待恢复到底在等待什么”的问题。沿用现有三端生命周期、数据库和 Agent 通道，不创建新的任务系统。

## 用户看到的变化

| 情况 | 页面与操作 |
| --- | --- |
| 只有配置、还未下发 | 未下发，使用原有下发入口 |
| 已确认停止 | 已停止，使用普通“启动” |
| 已确认运行 | 运行中，使用普通“停止” |
| 本次操作正在执行 | 启动中 / 停止中，禁止冲突操作；本次有截止时间 |
| 启动失败，原实例已确认停止 | 仍为已停止，单独显示失败原因；不自动再次启动 |
| 停止失败，原实例仍在运行 | 仍为运行中，单独显示失败原因；不自动再次停止 |
| Agent 离线或还没有可信现场事实 | 明确说明无法确认；不把它冒充成已停止，也不承诺自动恢复 |

没有“重试启动”“重试停止”“待恢复”的独立流程。在线但状态未确认时，用户仍使用普通启停入口；启动先做一次有时限的只读检查，无法核实就直接失败。原实例仍在运行时不重复启动，不通过偷偷关机、重建空机解决异常。离线删除和换 Agent 保留既有例外。

错误与机器是否运行分开。刷新、库存对账或重新连接可以更新机器事实，但不会把失败的那次操作改成成功，也不会抹掉失败原因；下一次明确操作被接受后才清除旧错误。

## 为什么不能只改按钮文字

截图中的“测2”原始字段是 `stopped`，但旧的 `cleanup_confirmed:false` 又令页面显示“重试停止”；徽标和按钮来自两套判断。“wai”所属旧会话离线，页面却称“待恢复”，暗示了一条并不存在的自动恢复流程。

现在 Server 计算一个 `lifecycle` 对象，同时用于操作准入和三端页面。页面只渲染它，不再独立分析原始状态、清理标记或端口。Agent 提供本次精确原生观察：机器电源事实、原生身份、资源是否释放、具体原因分别表达。停止不等于所有辅助端口已释放，运行也不等于自动化驱动已就绪。

## 保留的边界

- VM ID、AVD 名、iOS UDID、Harmony 实例目录与租约，以及原有端口分配范围不变。
- 已绑定实例的普通启动只允许原实例；缺失或身份不明时不新建替代实例。实际启动前还会在本机实例锁内核实，避免缓存丢失时重复起同一台机器。
- 已确认停止而配置文件损坏时，仍可如实显示停止；启动会具体报出配置问题，不能用清空数据绕过。
- 鸿蒙已停止但原租约对应的资源仍被占用、或释放情况无法核实时，普通启动明确失败并保留原盘和租约；页面不因此重新增加一个“停止”恢复步骤。修复宿主资源问题后，下一次普通启动会重新核验；没有承诺自动排除所有环境故障。
- iOS 原生实例 Booted 但 WDA 未就绪时，暴露原因，不隐式关机再启动；已 Shutdown 时只清理该实例自己的辅助进程。
- 任务、安装和观看占用保护保留；真实设备继续走原链路。没有增加定时业务重试、自动重建或自动迁移。
- 所有测试只作用于个人隔离环境；本轮不重复启动真实虚拟机，不操作公司环境。

## 接口与升级

没有新增数据库表或列，也没有改动三个平台的请求 URL、普通启停请求体和 VM ID。现有 `state` 字段保留以兼容旧客户端；实例响应及相关操作错误中的 `detail.instance` 增加 `lifecycle`：`state`、`agent_online`、六项布尔 `actions`、`notice`、`error`。历史失败和观察保存在原有 runtime JSON 中。

Agent 的现有 capability 通道增加 `inspect_instance` 只读请求和 `details.instance_observation` 结果。检查有有限预算，不执行创建、停止或删除；不支持新观察的旧 Agent 不能凭旧标记放行未知实例启动。

本轮没有新增 CLI 命令或强制要求修改已有请求。普通 Stop API 保留一次显式、幂等的原生核验与真实回执；页面已停止时不再提供多余的停止按钮。需要呈现新统一状态的客户端应读取 `lifecycle`，不能继续把 raw `state:error` 当成机器一定未运行。

Server、页面和 Agent 应成套更新，保留原数据库、宿主身份文件、原工作目录和全部原生实例数据；先 Server、后 Agent。存量机器不需要删除重建。已有升级注意事项仍见[升级交接说明](../../vm-lifecycle-upgrade-guide.md)。
