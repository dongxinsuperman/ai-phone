# 虚拟机生命周期约定

这份约定适用于现有 Android、iOS Simulator、Harmony 虚拟机页面和 API。沿用现有配置表、Agent 通道和原生驱动，不引入另一套编排系统。2026-10-16 的修复与验收记录见 [验收结果](experiments/vm-lifecycle-audit-20261015/execution/RESULT.md)。

## 用户操作

| 操作 | 成功后的含义 | 失败、离线时的处理 |
| --- | --- | --- |
| 创建 | Server 新建一条配置，未绑定 Agent，也未创建原生实例。 | 创建事务失败就不保存。 |
| 探查 | 返回当前 Agent 的环境和承接能力。 | 明确返回失败或超时；不把无响应当成可用。 |
| 首次下发 | 目标 Agent 新建并启动实例，Server 收到本次运行成功回报后确认绑定。 | 本次操作结束；配置保留并显示失败，不自动重试。只有本次实际新建的资源才允许回滚删除。 |
| 启动已绑定实例 | 在原宿主、原实例上启动，保留原有数据。 | 缺少原实例就报错，不偷偷重建；失败不删除既有数据。 |
| 停止 | 确认原生实例已经停止，保留配置、绑定及数据。 | 未证明停止就显示失败，不能据此重新分配仍可能被占用的端口。 |
| 删除 | Server 当场删除配置、别名及旧设备路由。 | **允许 Agent 离线。** 在线只发送一次精确清理，遗漏的原生残留在 Agent 重连时对账清理。 |
| 换 Agent | 在同一个数据库事务中撤销旧配置并创建新 ID 的空白配置，再向目标 Agent 启动一次。 | **不等待旧 Agent 上线或清理完成。** 新启动失败不会恢复旧配置，也不会后台继续启动。 |

下发和停止中的 `starting`、`stopping` 是本次原生操作的进度，有明确截止时间；它们不是一个等待恢复的订单。启动过程中拒绝冲突操作；运行中的设备仍需先停止再删除或换机。在线执行任务、安装或观看时保留原有占用保护。

Android 普通停止先确认一次受管实例的系统同步，再按原快照策略退出；同步失败或身份不清就报错，不自动继续杀进程。显式删除及本次确实新建资源的失败回滚仍可准确销毁。保留数据指不删除或重建原实例和存储，不等于任意 App 尚未提交的内存写入也已经落盘；具体快照/擦数据策略仍按原配置执行。

删除成功表示总账已删除，不表示离线电脑上的文件已经消失。页面不增加“待清理订单”或要求用户等待旧 Agent；原生残留的处理只属于对账。

## 身份与三端限制

| 平台 | 配置身份 | 宿主上的实例与通道 |
| --- | --- | --- |
| Android | 现有 VM ID | 受管 AVD 名对应 VM ID；运行时需要可用的 emulator 控制/ADB 端口，不能抢占外部实例。 |
| iOS Simulator | 现有 VM ID | 受管名称和原生 UDID 对应同一实例；WDA/MJPEG 使用独立端口，停止不释放实例归属。 |
| Harmony | 现有 VM ID，设备侧使用 `harmony-vm:<id>` | 本地注册表保存实例目录和原生租约，HDC 端口只用于连接，不能替代配置身份。 |

Android 已有实例启动或复用前核对实际 SDK 镜像包与有效请求；配置不符或资料不完整就拒绝，既不改旧盘，也不自动重建。恢复正确配置后仍可使用原实例。

Android 已有数据分区容量大于或等于请求时保留原值，配置不变时不重写文件；较大请求仍沿用原 SDK 路径。容量资料不明时写入前失败，不缩小、不删除旧实例。请求容量不等于 SDK 实际配置容量，正常升级不能批量改成某个测试环境的数值；内存快照是否恢复仍取决于原策略及实际配置兼容性。

VM ID 与原生通道分开处理，保留既有 ID 格式和已有配置。端口复用不能继承上一台机器的别名、运行状态或执行结果。Server 删账并不证明宿主端口已经空闲；若本次下发遇到仍被占用的槽位，明确失败，不抢占或偷偷改用另一端口。Agent 安装目录持久保存宿主身份，每次连接仍使用独立会话身份；复制安装目录时不能把宿主身份文件复制到另一台电脑。

重连只接受同一宿主的确切实例证据；旧版本记录缺少宿主身份时，只在旧会话离线且原生证据匹配时补齐。不同宿主报告相同 VM ID 不会自动抢走总账归属。所有生命周期回报核对操作 ID 和截止时间，旧操作的迟到回报不能覆盖新操作。

## 对账的边界

Server 保存总账，Agent 报告本机受管实例、查询是否完整以及原生身份凭据：

1. 本机有实例、Server 已无配置：凭确切身份清理本机残留。
2. 本机有实例、但与 Server 记录的安装身份冲突：不接管、不删除，维持原归属并记录冲突；两份 Agent 安装可能看见同一份原生实例，不能据此认定存在可删的多余副本。
3. Server 有配置、本机确实没有实例：记录异常，不自动重建或重新执行失败的下发。
4. 原生扫描失败、信息不完整：不能推断实例不存在，也不能据此释放资源或删除不明实例。
5. 首次绑定失败后有迟到实例：只有本次确实创建它的证据才允许清理；不能误删本就存在的数据。

保留原有连接重建和状态回报补送；补送的是同一次操作的结果，不是重新执行启动。没有新增定时重试、自动迁移、自动补建或后台接力的业务流程。

旧版清单缺少完整性声明时不作为缺失/停止证明。旧鸿蒙未确认租约只有在完整清单、准确实例资料和原租约全部吻合时才接续原会话；仍保留未确认状态与租约，再由普通停止操作检查实际资源，不能把旧的 `ready=false` 当作停止成功。

## 扫描、执行和真实设备

三端发现工作相互隔离，每端同时最多一轮；耗时扫描不阻塞 WebSocket 命令处理，也不能用旧扫描结果覆盖新结果。静态环境信息可以短时缓存，但内存、端口和实际运行情况必须重新检查。就绪探针有有限工作线程和排队上限，迟到的旧实例结果失效。

VM 启停、自动维护、执行任务、安装卸载及观看共用已有设备活动边界。只有确认运行且身份一致的受管 VM 才能重新进入可执行状态。真实设备不套用 VM 的总账删除规则；可选 VM 数据表不可用也不能拖垮真实设备上报。

## 验证范围

2026-10-16 在个人隔离环境验证，未向公司环境部署或下发任务。单测覆盖网络断开、迟到回报、并发操作、缺失实例、端口复用和旧数据保护；实际原生测试使用同一个个人合成页面验证输入、确认、停启数据保留及清理。

存量配置和原生实例不需要重建；本轮保护需要相应的 Server、Agent 和页面代码更新，旧 Agent 不会因为只升级页面而自动获得新行为。首轮三端原生验收使用同一批修复代码；后续补丁与分平台原生复验按准确提交另记，不作为任意混合版本的兼容承诺。

实际原生结果不能替代未执行的 Windows 宿主验收、真实手机验收、iPad 原生验收或生产 VLM 业务验收。每项通过范围、失败轮次与清理证明均在验收记录中单列。

完整的新旧差异、端口唯一范围、API/CLI 兼容与已有机器升级步骤见 [升级交接说明](vm-lifecycle-upgrade-guide.md)。原生验收与后续升级补丁的隔离回归按各自源码版本分别记录。
